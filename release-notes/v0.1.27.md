# v0.1.27 — Harness 0.2.1-rc.3 cohort (fork build)

Fork build for the `0.2.1-rc.3` desktop core; recommended host: Harness `0.2.1-rc.3`.

- Add `0.2.1-rc.3` as the recommended host target and demote `0.2.1-rc.2` to `legacy`; `0.2.1-rc.1` and older targets keep their existing tracks.
- Enumerate `0.2.1-rc.3` in all 21 DSH peer ranges. The host installation gate compares the declared range against the running core, so a missing entry rejects the package before activation — the failure mode reported in
  [upstream #277](https://github.com/NanmiCoder/dsh-agent-teams/issues/277).
- Move the development cohort and every `pnpm-workspace.yaml` override to `0.2.1-rc.3`, so `@deepseek-ai/dsh` and the 304 pinned DSH packages resolve one exact version.
- No product-source changes. `lib/` is rebuilt from the same `src/` tree; the only source-adjacent edit is the verification runner's Windows `npm` spawn shim.
- `scripts/harness-runtime-verify.mjs` now routes `npm` through `%ComSpec%` on Windows: `CreateProcess` appends `.exe` only, so the `npm.cmd` shim is unreachable from a bare `spawn('npm')` and the runner previously died with `spawn npm ENOENT`.
- `scripts/compatibility.test.mjs`, `scripts/harness-runtime-verify.mjs` and the CI matrix assert the new recommended target instead of the previous one.

Install this fork from the checkout, not from npm:

```sh
dsh plugin --profile desktop add --save-exact <path-to-this-checkout>
```

Replace `desktop` with your profile name and restart that profile's Harness process after installation. Plugin and host versions are independent; this release does not upgrade the host.

Verification evidence for this release is recorded in [docs/harness-0.2.1-rc.3/README.md](../docs/harness-0.2.1-rc.3/README.md), together with the artifact digest. Runtime scenarios use real Harness sessions, tools and sub-agents with deterministic model fixtures; real provider credentials, browser interaction and live desktop acceptance are outside that coverage.
